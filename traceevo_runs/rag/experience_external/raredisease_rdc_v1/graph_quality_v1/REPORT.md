# 因果图合法性与合理性评测

2026-10-13。读取两批40例已封存病例的所有因果图快照，原图、审计事件和诊断结果保持不变。

## 合法性：程序硬规则

检查图容器、节点类型、空标签、假设置信度范围、层级、悬空边、自环、重复边、支持/反驳目标、refines层级、父假设缺失、多父关系和细化循环。

规则保留当前GoS的Signal→Hypothesis锚定边；真正的层级细化使用Hypothesis→Hypothesis。合法性是这些新增明确规则的合规结果，不是医学正确性，也不是已验证的异常检测准确率。

| 指标 | 结果 |
| --- | ---: |
| 最终图通过 | 27/40，67.5% |
| 所有快照通过 | 26/40，65.0% |
| 子假设缺少父假设连接 | 13个节点 |
| 假设标签重复 | 6处 |
| 支持/反驳边目标类型不符 | 4条边 |

这些规则需要与项目图结构规范及医学专家确认，特别是层内新增假设是否需要绑定当前父假设。原图更新校验与新增图评测约束的差异也可能造成不通过。

合成单元反例覆盖悬空边、重复边、非法分数、父子层级错误、refines循环、父假设缺失、重复假设和错误目标。它们用于验证检查器能识别已知违规，不当作真实病例上的Precision/Recall。

## 合理性：来源约束审计

新增只读评测入口，复用现有审计智能体提示词：检查证据真实性与绑定、假设是否合理细化、支持/反驳含义、置信度理由、报告触发条件。输入为初始病例信息、因果图、审计溯源图、真实检索原文和FSM记录。检索原文从TOOL_CALL事件重建，兼容旧EVIDENCE_READ格式；不会把没有text的记录元数据当原文。

审计智能体必须提供根事件、根节点、理由、查过的记录ID和逐字引句。程序核对ID存在性、引用原文及记录覆盖。模型不删除图，评测入口也不执行回滚。

已在新批次case-6试跑。首次输入兼容问题及引用校验失败的原文保留；补全事件中的原始检索内容后重新审计，模型仍未完整列出全部检索记录，严格校验拒绝该判断，最终计UNCERTAIN。不能把这次输出当作已确认的异常。

## 下一步怎样形成真正的评测指标

由医学专家对独立轨迹逐节点、逐边标注问题类型和根事件；同时建立有明确答案的异常注入对照，例如无来源检查、错绑病例、错误细化、支持边反向、置信度理由冲突和违规报告。

分别报告：证据可追溯率、细化关系合理率、支持/反驳语义正确率、异常检测Precision/Recall、根节点与根事件定位准确率、正常图误报率、UNCERTAIN比例。结构指标、人工语义指标与模型代理评分分开。

当前缺少人工语义金标准，暂不声称语义审计检测准确率。此评测衡量推理结构与来源质量，不替代最终诊断准确率。
